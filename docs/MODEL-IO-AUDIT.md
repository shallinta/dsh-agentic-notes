# 模型输入输出边界审计

## 结论与当前配置

随记不再为模型请求填写自己的输出 token 配额，也不再按字符估算上下文窗口后裁掉内容。实际模型容量由 DSH 适配器和服务商配置决定。

用户已明确选择将以下三项公开设置全部改为 **0（不限）**：

| 设置 | 含义 | 当前值 |
| --- | --- | --- |
| `toolResultMaxChars` | 内部 Agent 接收的工具结果文本 | 0 |
| `webFetchMaxChars` | 内部 Agent 接收的网页正文 | 0 |
| `readNoteMaxChars` | 内部 Agent 单次读取的笔记正文 | 0 |

三项设置的新默认值也都是 0。以后只有显式保存非零整数才启用相应字符限制；不会再强制最低 1000、最高 200000。截断内容会附设置名称、返回字符数、原字符数和解除方法，不能冒充完整内容。字符计数不拆开 emoji 的代理对。

不限可能增加请求体积、处理时间和 token 费用，也不表示模型具有无限上下文。服务商拒绝过大的输入时呈现原错误，不通过减少资料或切换到信息更少的引擎伪装成功。服务商以 `max-tokens` 结束生成时，不执行尚未完成的输出。

## 已移除的隐藏数量限制

| 路径 | 原行为 | 当前行为 |
| --- | --- | --- |
| 全部模型请求构造 | 分类、规划、元信息等调用写入 400、500、900、1200、1400 等 token 值；部分调用强塞估算出的默认输出值 | 请求构造器不接受或填写这些配额，所有模型调用遵循适配器与服务商配置 |
| 页面上下文 | 26000/40000/12000 字符预算、单文件 5000 字符、估算窗口的 80% | 当前业务范围内的正文完整提供，不用字符数冒充 token 预算 |
| 原生引擎上下文封装 | 将序列化后的页面资料再截到 20000 字符，可能连 JSON 都不完整 | 页面资料完整序列化 |
| 首页与资源清单 | 最多 300 篇笔记、500 个附件，日记只给最后 4 册，待办只给前 120 项 | 当前范围内完整列出；首页仍明确只给元数据，不自动发送全库正文 |
| 历史消息 | 只给最后 8 条，每条最多 6000 字符 | 保留全部传入消息及完整内容，原生初始请求也保留传入历史；历史不代替本轮授权 |
| 笔记与工具读取 | ReAct 正文最多 8000 字符，工具观察默认 20000；网页也有硬编码裁剪 | 仅按上面的公开设置处理，当前均不限 |
| MCP 搜索 | 命中文本只返回前 200 字符 | 随记端返回完整命中文本；外部客户端自己的额度不由插件覆盖 |
| 元信息与维护规则 | 只取前 20 篇标题、样本前 200 字符、前 3 本笔记本和前 30 条操作；描述、关键词、规则等又被裁短 | 辅助请求接收完整选定资料，完整保存返回字段，不再丢掉尾部约束或关键词 |
| 模型生成结果 | 只保留前 50 个操作；选项只保留 6/8 个，ID、标签、描述、待办文本等被静默裁短 | 保留全部合法操作和选项、完整字段；写入仍须通过权限、冲突和确认检查 |
| 长文处理 | 限 12 节、前文只保留 3500 字符、原文只取前 12000；按猜测的字符预算切节 | 大纲完整保留，前文与参考原文不裁剪；分节只按内容结构组织，不丢弃节内文字 |
| 额外执行配额 | 原生主循环另有 60 次工具调用限制，影子校验与归类还有各自的固定轮次 | 不另设隐藏工具次数配额；按设置页公开的 ReAct 最大轮次处理 |
| 会话与日志记录 | 只记前 40 个工具，单条日志/动作记录最多 20000 字符 | 记录完整工具过程与文本，日志保留天数仍按公开设置清理 |

## 保留的不同性质边界

这些边界不是模型文本的隐藏剪裁，不能把“取消配额”理解成绕过权限、确认或资源保护。

### 模型与服务商

- 实际上下文容量、输出容量、模型模态和服务商请求策略仍有效。插件不伪造更大的模型窗口，也不悄悄截掉原文来掩盖错误。
- 用户明示的字符设置、公开的 ReAct 最大轮次仍可生效。默认轮次 20，设置范围 1—50；归类、原生、JSON 和影子校验使用同一项设置。
- 原有模型辅助调用的等待超时仍保留：按调用种类为 30、60、90、120 或 300 秒。它们是执行超时，不是 token 或字符配额；本次没有取消这些超时，也没有把它们改成新的输入输出数量上限。原生主模型循环没有额外填入这组超时。

### 授权与写入安全

- 页面范围、路径越界、私有元数据保护、只读 `manualRules`、冲突检测和用户确认继续执行。
- 500 字等条件用于判断是否需要审阅，不截取输入或输出。批量操作超过审阅阈值时保留全部操作供确认，不只执行前几条。
- JSON 引擎每轮最多一个写工具是事务组织规则；该工具可携带完整操作数组。等待用户或执行 `finish` 后，剩余工具会收到明确的“未执行”结果。
- 既有标题/文件命名规范仍为最长 60 字；日记约 5000 行分册。这些规则已在功能规格中说明，不截断模型读取的笔记正文，也不丢弃其它册。

### 上传与网络保护

- 插件 HTTP 请求体上限 4 MiB，网页原始响应上限 5 MiB；超出时报错，不返回一个假装完整的前缀。HTTP 请求体上限也包含上传编码开销。
- 图片入口已有明确的最多 9 张、单张最多 10 MiB 规则，且仍受上面的 HTTP 请求体积约束。服务端收到超过 9 张有效图片会拒绝整次输入，不再静默只发送前 9 张。
- 网页抓取保留 SSRF 校验、IP 绑定、最多 6 次重定向，以及设置页公开的抓取超时；不因此省略已经取得的正文。
- 封面、音频等上传也保留各自明确报错的文件体积检查。这些不构成模型正文配额。

### 显示预览

- 提示区只显示最新三张，但队列保留其余卡片。
- 首页关键词预览、会话列表标题/预览、系统通知和语音播报可使用短文本；原数据与模型正文不受这些显示长度影响。
- 输入回溯和会话列表有显示条数范围，日记页近期归档索引也有窗口；它们不作为模型历史或文件读取的长度预算。
- 文件切分、提取 JSON、去除 Markdown 标记、生成短 ID 等正常解析操作不是数量限额。目录元数据中的摘要不冒充正文，正文可通过读取工具完整取得。

## 验证

[模型输入输出回归测试](../test/model-io.test.mjs)包含长正文尾部标记、完整 JSON 上下文、全部历史、超过旧清单数量的输入、完整选项与操作、长维护规则与待办、显式限制提示、辅助元信息与规则沉淀、超过旧工具调用数量、MCP 完整搜索、服务商上下文拒绝和截断输出安全等用例。

审计初始的七组完整链路测试全部失败，移除对应限制后通过。服务商拒绝上下文后自动回退并伪成功的用例也先复现为失败，再修复。网络权限和写入确认测试继续保留。

未使用用户的真实笔记做自动写入或重试测试。测试数据位于隔离临时目录；运行时只按用户明确选择修改了上述三项公开配置。
